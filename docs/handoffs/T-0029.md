# T-0029 — Learner answer-type expansion

Status: review.

## Delivered

- Additive migration `0021_add_response_aware_attempts.sql` adds response-aware attempt payloads without altering historical MCQ attempts.
- Question response types now include `multi_select`, `exact_short_answer`, `numeric_answer`, and `essay`; existing `short_answer` and `structured_response` remain written-response types.
- Rubrics validate exact response-aware answer keys: option-set equality, normalized accepted strings, or numeric value plus non-negative tolerance. Written responses reject answer keys.
- Learner attempts persist submitted answers. Multi-select, exact text, and numeric responses receive deterministic marks only after submission; written response submits as `pending_review`.
- Learner projection never includes answer keys. Existing provenance, grounded-source, current canonical-rubric, and verified-node gates remain live.
- Practice renders MCQ, multi-select, exact/written text, and numeric controls. Editorial question form exposes response types and option editing for multi-select.

## Deferred follow-up

- Editorial rubric form needs dedicated controls for multi-select answer sets, accepted-answer lists, and numeric tolerance. Core API supports these strict shapes now; no runtime content was created.
- Exam Mode renders and submits mixed response types. Its result screen never invents a score for
  `pending_review` written responses.
- Written response requires human marker workflow; `pending_review` deliberately has no score.
