# T-0034 handoff — automated Sonnet written-response marking

Status: done / released as a fake-provider-only foundation. Live provider configuration and
calibration remain deferred.

## Delivered

- Additive migration `0024_create_written_marking_requests.sql`: one owner-scoped request per
  submitted written attempt, immutable accepted result and append-only events.
- Core learner-only `POST`/`GET /learner/attempts/{id}/marking`, with ownership, response-type,
  submitted-state, pinned-rubric checks, idempotent request creation, retry/withhold, and strict
  criterion-result validation.
- Narrow HTTPS Core-to-AI adapter using a separate service bearer token. It carries private answer
  and criterion context only in memory to the service-only provider boundary; this material is
  never persisted in T-0033 jobs/traces, events, logs, learner routes, or public job responses.
  When unconfigured it leaves state pending; no mark is fabricated.
- AI service-only `/sonnet/marking-jobs` endpoint guarded by `SIDUS_CORE_SERVICE_TOKEN`; it reuses
  T-0033's fake provider and quality gate. No provider/key/live call exists.
- Fixed learner BFF route and Practice UI state for pending/accepted/withheld results.

## Deferred

## Review fixes

- Concurrent idempotent requests now use `ON CONFLICT DO NOTHING` followed by an owner-scoped
  re-read, so duplicate races cannot surface as a database 500.
- Both pre-existing and conflict re-read paths propagate the same nonblank request id to the
  marker. Repeated HTTP and concurrent PostgreSQL regression tests prove a marker cannot be
  invoked with an empty or unstable id.
- One accepted idempotent POST performs up to three automatic provider/gate attempts before
  withholding; it never requires a learner to repeatedly click retry.
- The private answer payload and criterion descriptors now cross only the TLS service-token
  Core-to-AI boundary and are passed to a capable provider in memory only. They are absent from
  public `SonnetRequest`, SQLite job JSON/traces, learner projections, browser routes, audit
  events, logs and public job responses. The fake provider is still the only provider enabled.
