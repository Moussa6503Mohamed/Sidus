## Delivered

A local-only authenticated browser E2E harness for `apps/web` that drives the real
signed-in UI → BFF → Core path against the isolated T-0023 `sidus-local-import` HTTPS stack.
See `docs/e2e-harness.md` for the operator guide and `docs/decisions.md` D-0023 for the rationale.

- **Dependency:** `@playwright/test` 1.62.1 added to `apps/web` devDependencies, exact-pinned.
  Dependency-risk check: Apache-2.0; four-package tree (`@playwright/test` → `playwright` →
  `playwright-core`, plus macOS-only optional `fsevents`); zero advisories; published 2026-08-10;
  dev-only, so no runtime or bundle impact. Verdict: add. Chromium was installed into the machine's
  Playwright browser cache (outside the repo) so the harness is runnable.
- **Interactive auth capture** (`e2e/auth.setup.ts` + `playwright.auth.config.ts`, script
  `e2e:auth`): opens a headed browser, waits up to ten minutes while the **human** signs in to
  Clerk, confirms the session survives a fresh server-rendered `/dashboard` request, then saves
  storage state plus a capture-time sidecar under `D:\Sidus-private-content\e2e`. The harness
  never handles a password, email, Clerk secret key, or bearer token, and prints only the profile
  name.
- **Fail-closed storage-state library** (`e2e/lib/storage-state.ts`): refuses any state path
  inside the repository; rejects missing, unparseable, cookie-less, expired, or older-than-8-hours
  captures with actionable instructions; never lets a cookie value into an error message. All
  three profiles are required by default — a profile is dropped only by an explicit
  `SIDUS_E2E_PROFILES` narrowing (`none` runs the signed-out suite alone).
- **Runtime-only synthetic fixtures** (`e2e/lib/synthetic.ts`): every value is
  `SIDUS-E2E-SYNTHETIC-<nonce>-<field>`, verified by `assertSynthetic` before the first keystroke,
  so no educational, past-paper, mark-scheme, or source-derived text can reach the database. A
  fresh nonce per run also keeps Core's unique `sourceUrl` constraint satisfied on repeat runs.
- **Stack preflight** (`e2e/lib/preflight.ts` + `e2e/global-setup.ts`): checks Core over real TLS
  and the web app before any browser opens, distinguishing "stack down" from "CA not trusted" and
  turning each into an instruction.
- **Journey spec** (`e2e/editorial-to-practice.e2e.ts`), one test in ten UI-driven steps: pending
  synthetic source → approve → create node → verify node → create MCQ draft → create rubric
  version → verify rubric → choose canonical + verify question → Practice selection → submit →
  feedback visible.
- **Negative specs:** `denial-learner.e2e.ts` (editorial pages **and** the editorial BFF refused,
  Practice still reachable), `denial-unknown.e2e.ts` (editorial *and* Practice refused, in the UI
  and at Core), `fail-closed.e2e.ts` (signed-out redirects, both BFFs refusing anonymous callers,
  a forged/expired session cookie buying no trust).
- **Tool tests** in the normal Vitest suite: `e2e/lib/storage-state.test.ts` and
  `e2e/lib/synthetic.test.ts` (+37 tests, 289 → 326). Capture-time sidecar evidence is now
  mandatory: missing, damaged, mismatched, stale, non-finite, or future timestamps fail closed.

Not done, by design: no auth bypass or fake-auth mode; no credential material in the repo; no
Playwright trace/video/screenshot artifacts (they embed live session cookies) and `outputDir`
outside the repo; no `ignoreHTTPSErrors`; no migration seed or committed fixture content; no
`docker compose down` and no record deletion — the operator's stack and data are left running for
manual testing; no push.

## Decisions / assumptions

- D-0023 records the design. The five load-bearing properties: no auth bypass, no credential
  material in the repo (including artifacts), fail-closed rather than silently unauthenticated,
  real TLS, and runtime-only opaque content.
- The `admin` profile drives the whole journey because that single role legitimately holds both
  editing and reviewing permissions, and every recognized role holds `learner_question:read`.
- Denial is asserted at the BFF/Core layer as well as in the UI: the web-side role check is
  cosmetic by design (D-0006/D-0011), so a rendered "No editorial access" is not evidence.
- Assumed and documented, not automated: the operator runs the stack and the dev server, and adds
  `http://localhost:3001` to `CLERK_AUTHORIZED_PARTIES` in `.env.local-import` (the stack defaults
  to `:3000` only, so authenticated Core calls would otherwise `401`).
- The capture-age limit is 8 hours, checked independently of cookie expiry because a Clerk session
  can be revoked server-side without the cookie changing.
- On Windows/Node, a preflight failure prints its instruction and exits non-zero, followed by a
  cosmetic libuv `UV_HANDLE_CLOSING` assertion from Playwright's own shutdown. Noted in
  `docs/e2e-harness.md`.
- Local-only session config: `.claude/settings.local.json` (untracked, not staged) got
  `"worktree": {"bgIsolation": "none"}` so this task could run directly in the main workspace as
  instructed.

## Review and manual-auth gate

Independent review of the credential-handling and fail-closed paths is required before release.
The implementation commit is **not pushed**.

After review, the human operator can run the full harness:

1. Add `http://localhost:3001` to `CLERK_AUTHORIZED_PARTIES` in `.env.local-import`, restart the
   stack's `core` service.
2. Create/confirm the three Clerk users (`admin`, `learner`, and one with no `sidus_role`).
3. Capture each profile: `$env:SIDUS_E2E_PROFILE = "<profile>"; npm --prefix apps/web run e2e:auth`.
4. `$env:NODE_EXTRA_CA_CERTS = "D:\Sidus-private-content\local-dev\ca.pem"; npm --prefix apps/web run e2e`.

The `sidus-local-import` stack was left running and no record was created, deleted, or modified in
it by this task.
