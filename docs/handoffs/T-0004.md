# T-0004 handoff

**Status:** done / released
**Owner:** Claude Code agent
**Depends on:** T-0001 (done), T-0002 (done), T-0003 (done)

## Goal

Safe, metadata-only multi-subject curriculum catalogue so future approved Cambridge
syllabuses onboard without code changes. Remove hard-coded `0610`/`5090` validation; replace
with registry-backed validation. No content, questions, OCR, ingestion, or copyrighted data.

## Delivered

### Migrations (`services/core/migrations`)

- `0005_create_subjects_and_syllabuses.sql` — `subjects` (name UNIQUE) and `syllabuses`
  (board, syllabus_code, subject FK, qualification, nullable track, display_name, nullable
  curriculum_year, status `draft|active|retired`). Safe uniqueness
  `UNIQUE (board, syllabus_code, COALESCE(track,''))` + supporting indexes.
- `0006_create_syllabus_events.sql` — append-only, trigger-immutable catalogue audit trail.
- `0007_seed_biology_syllabuses.sql` — seeds **only** subject `Biology` and the two D-0004
  syllabuses (0610 IGCSE/Extended, 5090 O Level), both `active`. Idempotent (`ON CONFLICT`).
- `0008_link_content_sources_to_catalogue.sql` — adds nullable
  `content_sources.catalogue_syllabus_id` FK (`ADD COLUMN IF NOT EXISTS`, no data loss);
  drops the hard-coded `syllabus_code IN ('0610','5090')` CHECK.

### Core (`services/core`, Go)

- New package `internal/catalogue`: `model.go`, `store.go` (interface + errors),
  `postgres_store.go`, `handlers.go`. Endpoints: `GET/POST /catalogue/subjects`,
  `GET /catalogue/syllabuses` (active only), `GET /catalogue/syllabuses/{id}` (active only),
  `POST /catalogue/syllabuses`, `PATCH /catalogue/syllabuses/{id}`. Strict JSON decoding
  (unknown fields + trailing data rejected). Audit actor = verified Clerk subject only.
- `internal/auth/auth.go`: added `PermReadCatalogue` (editor/reviewer/admin) and
  `PermManageCatalogue` (admin only); learner/unknown denied by default.
- `internal/contentsource`: `Register` now takes a `SyllabusResolver`; create/PATCH resolve a
  supplied `syllabusCode` against the registry (unknown/inactive/ambiguous → `400
  unknown_syllabus` before any write; omitted → allowed) and store the resolved
  `catalogue_syllabus_id` FK alongside the code. Removed hard-coded `isValidSyllabusCode`.
- `main.go`: wires one catalogue store as both the catalogue API backend and the
  content-source syllabus resolver (single authority).

## Schema decisions

- Uniqueness is `(board, syllabus_code, COALESCE(track,''))` — code is not assumed globally
  unique; NULL track cannot silently duplicate a `(board, code)` pair; different boards may
  reuse a code.
- Seeds are `active` (confirmed first slice; must resolve for existing 0610/5090 metadata).
- `curriculum_year` left NULL for the seeds (task forbids inferring a year/edition).

## Migration path

Existing seeded `content_sources` rows keep `syllabus_code`, get `catalogue_syllabus_id =
NULL`, and are **not** auto-mapped — a human links them later. New writes resolve the code and
store the FK. Documented in `docs/curriculum-catalogue.md`.

## Review fixes (this pass)

Two review findings on the original T-0004 delivery, fixed while keeping status `review`:

1. **Subject-creation audit was dropped.** `POST /catalogue/subjects` already received the
   verified Clerk subject as `ActorID`, but `PostgresStore.CreateSubject` never wrote it
   anywhere. Added:
   - `services/core/migrations/0009_create_subject_events.sql` — new immutable `subject_events`
     table (`subject_id`, `event_type` CHECK `'subject_created'`, `actor_id`, `event_time`,
     `changed_fields TEXT[]`, `created_at`) with a `BEFORE UPDATE OR DELETE` trigger, mirroring
     `syllabus_events` (migration 0006).
   - `PostgresStore.CreateSubject` now runs the subject insert and the `subject_events` insert
     in one transaction; a failed audit insert rolls back the subject row. `changed_fields` is
     always `["name"]` — field names only, never the submitted value, never source material.
   - **Seed exception documented:** the Biology subject seeded by migration 0007 is a plain SQL
     `INSERT`, not the `CreateSubject` application path, so it carries no `subject_events` row
     and no invented actor id (bootstrap metadata, not a human action).
   - New tests: `TestPostgres_Integration_SubjectAuditAndImmutability` (records verified actor,
     names-only fields, duplicate creation records no event, UPDATE/DELETE rejected by trigger),
     `TestPostgres_Integration_SeededBiologySubject_NoSubjectEvent` (seed carries zero events),
     plus handler-level `TestCreateSubject_Success_RecordsVerifiedSubjectEvent`,
     `TestCreateSubject_Duplicate_NoNewEventRecorded`, `TestCreateSubject_Unauthorized_NoEventRecorded`.
   - Existing `syllabus_events` immutability test (`TestPostgres_Integration_EventImmutability`)
     re-verified green, unchanged.

2. **Catalogue handlers leaked raw internal error text.** All six `internal_error` responses in
   `internal/catalogue/handlers.go` (subject list/create, syllabus list/get/create/update) called
   `err.Error()` directly, which could surface DB/query/DSN details. Replaced with one stable
   constant, `internalErrorMessage = "an internal error occurred"`. Safe static domain errors
   (`duplicate_subject`, `duplicate_syllabus`, `unknown_subject`, `not_found`, `invalid_status`,
   `no_changes`) are unchanged — those messages are fixed strings on sentinel errors, never
   driver output.
   - New test `TestInternalError_NeverLeaksRawInfrastructureText` uses a `failingStore` that
     returns a raw, detail-bearing error (containing a fake password/host/table string) from
     every store method, and asserts every `internal_error` response body equals the generic
     constant and contains none of that text.
   - `contentsource` handlers were **not** touched (out of scope for this fix; only new
     catalogue endpoints were in scope).

Docs updated: `docs/curriculum-catalogue.md` (subject_events section, seed exception,
