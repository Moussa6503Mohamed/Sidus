# T-0004 handoff

**Status:** review
**Owner:** Claude Code agent
**Depends on:** T-0001 (done), T-0002 (done), T-0003 (done)

## Goal

Safe, metadata-only multi-subject curriculum catalogue so future approved Cambridge
syllabuses onboard without code changes. Remove hard-coded `0610`/`5090` validation; replace
with registry-backed validation. No content, questions, OCR, ingestion, or copyrighted data.

## Delivered

### Migrations (`services/core/migrations`)

- `0005_create_subjects_and_syllabuses.sql` — `subjects` (name UNIQUE) and `syllabuses`
  (board, syllabus_code, subject FK, qualification, nullable track, display_name, nullable
  curriculum_year, status `draft|active|retired`). Safe uniqueness
  `UNIQUE (board, syllabus_code, COALESCE(track,''))` + supporting indexes.
- `0006_create_syllabus_events.sql` — append-only, trigger-immutable catalogue audit trail.
- `0007_seed_biology_syllabuses.sql` — seeds **only** subject `Biology` and the two D-0004
  syllabuses (0610 IGCSE/Extended, 5090 O Level), both `active`. Idempotent (`ON CONFLICT`).
- `0008_link_content_sources_to_catalogue.sql` — adds nullable
  `content_sources.catalogue_syllabus_id` FK (`ADD COLUMN IF NOT EXISTS`, no data loss);
  drops the hard-coded `syllabus_code IN ('0610','5090')` CHECK.

### Core (`services/core`, Go)

- New package `internal/catalogue`: `model.go`, `store.go` (interface + errors),
  `postgres_store.go`, `handlers.go`. Endpoints: `GET/POST /catalogue/subjects`,
  `GET /catalogue/syllabuses` (active only), `GET /catalogue/syllabuses/{id}` (active only),
  `POST /catalogue/syllabuses`, `PATCH /catalogue/syllabuses/{id}`. Strict JSON decoding
  (unknown fields + trailing data rejected). Audit actor = verified Clerk subject only.
- `internal/auth/auth.go`: added `PermReadCatalogue` (editor/reviewer/admin) and
  `PermManageCatalogue` (admin only); learner/unknown denied by default.
- `internal/contentsource`: `Register` now takes a `SyllabusResolver`; create/PATCH resolve a
  supplied `syllabusCode` against the registry (unknown/inactive/ambiguous → `400

  `catalogue_syllabus_id` FK alongside the code. Removed hard-coded `isValidSyllabusCode`.
- `main.go`: wires one catalogue store as both the catalogue API backend and the
  content-source syllabus resolver (single authority).

## Schema decisions

- Uniqueness is `(board, syllabus_code, COALESCE(track,''))` — code is not assumed globally
  unique; NULL track cannot silently duplicate a `(board, code)` pair; different boards may
  reuse a code.
- Seeds are `active` (confirmed first slice; must resolve for existing 0610/5090 metadata).
- `curriculum_year` left NULL for the seeds (task forbids inferring a year/edition).

## Migration path

Existing seeded `content_sources` rows keep `syllabus_code`, get `catalogue_syllabus_id =
NULL`, and are **not** auto-mapped — a human links them later. New writes resolve the code and
store the FK. Documented in `docs/curriculum-catalogue.md`.
