# T-0036 handoff — teacher classes, consent, and assignments

**Status:** review

## Delivered

- Owner-scoped teacher classes with opaque SHA-256-hashed, expiry/use-limited invitations.
- Learner-only explicit acceptance and self-revocation; immutable consent events retain no token.
- Immutable teacher assignment settings and learner-safe item snapshots. Assignment creation rechecks verified question, rubric, module, and approved source eligibility.
- `automated` is the default and `manual_teacher` is accepted only as an explicit assignment value. No generic manual-review queue was added.
- Closed teacher and learner BFF operations/routes, minimal white-primary class/assignment UI states, and shared contracts.

## Privacy

Teacher roster entries expose opaque membership IDs and consent state, not learner profiles or answers. Teacher assignment data contains aggregate started/member counts only. Learner assignment delivery has no answer key, rubric, provenance, or source metadata.

## Deferred

- Completing an assignment through its own server-owned session is a follow-up; this task creates and delivers immutable assignment snapshots and records an idempotent start state.
- `manual_teacher` is a visible explicit assignment policy only. A scoped teacher marking workflow needs its own future task and must not become a generic reviewer queue.
