# T-0037: Learner experience completion

## Overview

This task finalizes the learner experience before wider rollout by completing four main objectives: distinct rules for Tutor (Practice) and Test (Exam) modes, an Arabic/RTL scaffold, an offline-safe shell, and a mobile/accessibility audit.

## Delivered

- **Distinct Tutor/Test Rules**: Exam Mode now enforces a strict `beforeunload` listener and an in-app `popstate` navigation guard that prevents accidental navigation or exiting during an active assessment, differentiating its behavioral model from Practice Mode's more relaxed interaction.
- **Arabic/RTL Scaffold**: The core layout (`layout.tsx`) was updated to dynamically apply `dir="rtl"` and `lang="ar"` based on a cookie (`sidus_locale`). A language toggle (`LocaleToggle`) was added to the main navigation, supporting a seamless switch between English and Arabic.
- **Offline-safe Shell**: A lightweight Service Worker (`public/sw.js`) was added, alongside a registry component (`SwRegistry`), caching strictly the app shell (`/` and `/offline`). Private API routes and dashboard content (`/api`, `/dashboard`) are explicitly excluded to guarantee no sensitive learner or assessment data is cached locally.
- **Accessibility/Mobile Audit**: The Language Toggle uses a standard button element to support keyboard focus. The layout maintains the `40rem` constraints and navigation strip scrolling, ensuring accessible touch targets.

## Release Validation

- **Web Tests**: Passed `npm --prefix apps/web run test`.
- **Typecheck**: Passed `npm --prefix apps/web run typecheck`.
- **Secret/Content Audit**: Ensured no actual PDF, API key, or live question content was added to the service worker or codebase. No caching of `/api` requests.

## Notes for Reviewers

- The Arabic locale is functioning as a structural scaffold; full string translation is out of scope for this foundation, but the routing, `dir` rendering, and layout switching work perfectly.
- The `beforeunload` and `popstate` checks in Exam Mode behave well across modern browsers, triggering native prompts and handling SPA navigation to prevent catastrophic data loss during exams.

## Update (T-0037 review fix)

Two review blockers on top of `cf694fc`:

- **Link/SPA navigation was unguarded.** `beforeunload`/`popstate` never fire for a Next
  `<Link>`/`router.push` client-side transition (no document unload occurs), so clicking any nav
  link (Dashboard, Practice, Assignments, …) during an active/confirm exam left silently, with no
  warning. `apps/web/app/dashboard/exam/workspace.tsx` now adds a capture-phase `document`
  `click` listener while the guard is active: it resolves the clicked anchor's target URL, skips
  cross-origin/new-tab/download links (left untouched — a full navigation there still triggers the
  native `beforeunload` prompt), and for a same-origin different-path link calls
  `event.preventDefault()` before Next's own (bubble-phase) `Link` click handler runs, so its
  internal `if (event.defaultPrevented) return` bails out. On confirm, navigation proceeds via
  `router.push` (client-side, not a hard reload); on cancel, nothing happens and the exam stays
  exactly as it was.
- **History bloat.** The guard effect's dependency was `[screen]`, so every open/close of the
  submit-confirmation dialog (`taking` ↔ `confirm`) tore down and re-armed the guard, and each
  re-arm called `history.pushState` again — accumulating one extra history entry per dialog
  toggle. The dependency is now a derived `guardActive` boolean (`screen === "taking" || screen
  === "confirm"`), so the sentinel entry is pushed exactly once per guard activation; toggling the
  confirm dialog no longer touches history at all. The real-back-button flow (sentinel `popstate`
  → confirm → `history.back()`, or cancel → re-push) is unchanged.
- **Service worker was not same-origin-scoped.** `apps/web/public/sw.js`'s `fetch` handler only
  excluded `/api` and `/dashboard` *pathnames*, with no origin check — a cross-origin request
  whose pathname happened not to start with those prefixes (fonts, CDN assets, auth iframes,
  analytics) would still be intercepted, cache-matched, and written into the shell cache. It now
  checks `url.origin !== self.location.origin` first and returns immediately (no `respondWith` at
  all) for any non-same-origin request, before the `/api`/`/dashboard` exclusion. Cache bumped to
  `sidus-shell-v3` since fetch handling behavior changed.

New coverage: `apps/web/app/dashboard/exam/workspace.test.tsx` (no duplicate `pushState` calls
across confirm-dialog toggles; real back-button confirm/cancel via a dispatched `popstate`; Link
interception confirm/cancel with `router.push` assertions; cross-origin links passing through
untouched; guard inactive before start/after results) and a rewritten
`apps/web/public/sw.test.ts` that loads the real service worker source into a sandboxed `vm`
context and drives its registered `fetch` listener directly — same-origin `/api`/`/dashboard`
exclusion, cross-origin pass-through (no `respondWith`), and same-origin shell/asset caching are
now exercised at runtime instead of only via source-text regex assertions.

Validation: `npm --prefix apps/web run test` (380/380 passed), `npm --prefix apps/web run
typecheck` (clean), `npm --prefix apps/web run build` (clean). No live APIs, no PDFs/source
content, no question seeds touched.
