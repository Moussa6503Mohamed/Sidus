# T-0006 — Curriculum-map foundation

**Status:** review
**Owner:** Claude Code agent
**Depends on:** T-0001 (done), T-0004 (done), T-0005 (done)

## Goal

Build metadata-only curriculum-map infrastructure for all subjects (topic maps, learning
objectives, practical skills, assessment rules), scoped under the existing curriculum
catalogue (D-0007), with a server-side source gate against the T-0001 rights register. No
syllabus text, objective wording, topic labels, assessment text, questions, mark schemes,
PDFs, extracts, diagrams, OCR output, or derivative content is created. No map data is seeded.

## What changed

### Database (`services/core/migrations`)

- `0010_create_curriculum_map_nodes.sql` — `curriculum_map_nodes`: `id`, `syllabus_id` (FK →
  `syllabuses`), `parent_node_id` (nullable FK → self), `node_kind` (CHECK: topic/objective/
  practical_skill/assessment_rule), `node_code`, `label`, `status` (CHECK: draft/verified/
  retired, default draft), `content_source_id` (NOT NULL FK → `content_sources`),
  `source_locator` (nullable), timestamps. Unique index `(syllabus_id, node_code)`.
- `0011_create_curriculum_map_events.sql` — `curriculum_map_events`: append-only audit
  (`node_id`, `event_type` CHECK node_created/node_updated/node_verified/node_retired,
  `actor_id`, `event_time`, `changed_fields`), `BEFORE UPDATE OR DELETE` trigger rejecting
  mutation — mirrors `syllabus_events`/`content_source_events`.

### Core Go service (`services/core/internal/curriculummap`, new package)

- `model.go` — `Node`, `Event`, `NodeKind`, `Status` types; `CreateInput`/`UpdateInput`.
- `store.go` — `Store` interface + domain error sentinels (`ErrNotFound`,
  `ErrDuplicateNodeCode`, `ErrUnknownSyllabus`, `ErrInvalidParent`, `ErrUnknownSource`,
  `ErrUnapprovedSource`, `ErrUnlinkedSource`, `ErrMismatchedSource`, `ErrNoChanges`,
  `ErrInvalidTransition`).
- `postgres_store.go` — `PostgresStore`: `CreateNode`, `UpdateNode`, `VerifyNode`,
  `RetireNode`, `GetNode`, `ListNodesBySyllabus`. Source gate (`validateSourceGate`) queries
  `content_sources` directly (status + `catalogue_syllabus_id`) inside the write transaction.
  Parent-same-syllabus + cycle prevention (`validateParent`) row-locks the candidate parent and
  walks its ancestor chain (bounded, `maxParentHops = 1000`) inside the same transaction —
  application-layer, not a DB trigger (see D-0008 "Alternatives" for why).
- `handlers.go` — `Register` mounts `GET/POST /curriculum-map/nodes`, `GET/PATCH
  /curriculum-map/nodes/{id}`, `POST /curriculum-map/nodes/{id}/verify`, `POST
  /curriculum-map/nodes/{id}/retire`, each behind `auth.Protect` with the new permissions.
  Strict JSON decoding (unknown fields / trailing JSON → `400 invalid_json`); PATCH uses a
  `map[string]json.RawMessage` pre-pass to distinguish "field absent" from "field present as
  null" for the nullable `parentNodeId`/`sourceLocator` fields. All domain errors map to stable
  codes; infrastructure failures always return the generic `internal_error` message.
- `handlers_test.go` — in-memory `Store` mirroring Postgres validation semantics; covers
  create success, unknown/inactive syllabus, pending/unlinked/mismatched/unknown source,
  cross-syllabus parent, duplicate code, parent-cycle prevention, non-draft PATCH rejection,
  full lifecycle (verify → re-verify rejected → retire → re-retire rejected), draft hidden
  from readers, missing `syllabusId` on list, full role matrix (learner/unknown denied, missing
  token 401, editor create-but-not-verify, reviewer verify/retire), strict JSON (unknown field,
  trailing JSON), invalid node kind, no-updatable-fields / no-changes on PATCH, and a table
  asserting every domain error maps to its documented stable code (never raw text).
- `postgres_store_test.go` — Postgres integration tests (skipped unless `TEST_DATABASE_URL`
  set): source gate against seeded active syllabuses with freshly-seeded approved/pending/
  mismatched sources; parent-same-syllabus + cycle rejection; duplicate code + full lifecycle
  with the exact three-event audit sequence; event-row immutability (UPDATE and DELETE both
  rejected by the trigger).

## Schema decisions (also recorded in D-0008)

- **Parent-same-syllabus and no-cycle checks are application-layer**, not DB triggers: a bare
  trigger would either leak raw `RAISE EXCEPTION` text to the client or force Core to
  fragile-parse trigger message text to recover a stable error code. Instead, `postgres_store.go`
  validates inside the write transaction with `SELECT ... FOR UPDATE` row locks on the parent
  chain, so the check is race-safe and the error mapping stays exact (`ErrInvalidParent`).
- **`syllabusId` is immutable after creation** (no `PATCH` field for it): changing it would
  require re-validating an entire subtree's parent-syllabus invariant in one write. Creating a
  new node under the correct syllabus is simpler and cannot leave a partially-migrated
  hierarchy.
- **Source gate re-runs on every `contentSourceId` change**, not just at creation — a draft
  node could otherwise be repointed at an unapproved/mismatched source after creation.
- **`status` is never a `PATCH`-able field** — only `verify`/`retire` actions change it, so the
  lifecycle transition rules live in one place (`transitionStatus`) instead of being
  reachable through the general update path.
