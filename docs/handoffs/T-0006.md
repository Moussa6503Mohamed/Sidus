# T-0006 — Curriculum-map foundation

**Status:** review
**Owner:** Claude Code agent
**Depends on:** T-0001 (done), T-0004 (done), T-0005 (done)

## Goal

Build metadata-only curriculum-map infrastructure for all subjects (topic maps, learning
objectives, practical skills, assessment rules), scoped under the existing curriculum
catalogue (D-0007), with a server-side source gate against the T-0001 rights register. No
syllabus text, objective wording, topic labels, assessment text, questions, mark schemes,
PDFs, extracts, diagrams, OCR output, or derivative content is created. No map data is seeded.

## What changed

- `0010_create_curriculum_map_nodes.sql` — `curriculum_map_nodes`: `id`, `syllabus_id` (FK →

## Review-fix pass (2026-08-04, on top of commit `b1677cb`)

Four findings from independent review, all fixed within T-0006 scope. Unchanged by this pass:
"no map data seeded", source/provenance approval rules, node schema purpose, role matrix,
public content restrictions, Clerk setup, other services.

### Fix 1 — PATCH strict-JSON bypass (`handlers.go`)

`updateNode` decoded into `map[string]json.RawMessage` (needed to tell "absent" from "present as
null" for the nullable fields) with `dec.DisallowUnknownFields()`, which **has no effect on a
map destination**. Unknown fields — `actorId`, `reviewerId`, `syllabusId`, `status`, `id`,
`createdAt`/`updatedAt`, and typos — were silently accepted and dropped.

- Added `updatablePatchFields`, the exact case-sensitive allowlist of the six PATCH-able names;
  any other key returns stable `400 invalid_json` **before** any store call.
- Re-decode of the normalized body into `updateNodeRequest` now uses a `json.Decoder` with
  `DisallowUnknownFields` (was a plain `json.Unmarshal`), so the struct layer is strict too.
- Trailing values/junk after the object still rejected (`{...}{}`, `{...}[1]`, `{...}not-json`,
  `{...}"extra"`).
- Absent-vs-null preserved: `parentNodeId`/`sourceLocator` may still be explicitly `null` to
  clear; absent leaves unchanged.
- Single `writeInvalidJSON` helper is the only strict-decode rejection body; it never echoes the
  offending field name.

### Fix 2 — source gate re-validated on every node write (`postgres_store.go`)

Was: gate ran on create and only when `PATCH` changed `contentSourceId`. A source approved and
linked at create time can later be un-approved, unlinked, or re-linked elsewhere, after which a
node could still be edited and even promoted to `verified` outside the T-0001 rights gate.

- `UpdateNode`: after the row lock and draft check, and **before** any diff/UPDATE/event, the
  gate runs against the *effective* source — `in.ContentSourceID` if supplied, otherwise the
  stored `content_source_id` — against the node's immutable `syllabus_id`. The old
  change-only gate call was removed (now redundant).
- `transitionStatus` (backing `VerifyNode` and `RetireNode`): the gate runs against the node's
  stored source before the status UPDATE and its event.
- Failures return the existing stable `400`s (`unknown_source`, `unapproved_source`,
  `unlinked_source`, `mismatched_source`); everything happens inside the write transaction, so a
  rejection leaves no node mutation, no status transition, no event, and no `updated_at` change.
- Gate remains Core-only; the AI service was not touched.
- **Accepted consequence (documented):** a node whose source has regressed is frozen — it cannot
  be edited, verified, *or retired* — until the source is restored via the content-source API.

### Fix 3 — syllabus validation on map list (`postgres_store.go`, `handlers.go`)

`ListNodesBySyllabus` returned an empty `200` for an unknown or inactive syllabus, making a typo
indistinguishable from a real-but-unauthored map (the normal state today, since no map data is
seeded).

- The store resolves the syllabus first and returns `ErrUnknownSyllabus` unless it is `active`.
- `listNodes` now routes store errors through `mapNodeError`, so this surfaces as the existing
  stable `400 unknown_syllabus`.
- A known active syllabus with zero verified nodes still returns `200` with an empty list.

### Fix 4 — real ancestor row locking (`postgres_store.go`)

`validateParent` locked only the candidate parent; the cycle walk used plain `SELECT`s, so the
"row-locked ancestor chain" claimed by D-0008/`curriculum-map.md` was not true and a concurrent
re-parent could be interleaved.

- The walk's query is now `SELECT parent_node_id ... FOR UPDATE`, locking every traversed
  ancestor inside the writing transaction.
- `sql.ErrNoRows` mid-walk maps to `ErrInvalidParent` rather than leaking an infrastructure
  error.
- Bounded traversal (`maxParentHops = 1000`) and `invalid_parent` mapping unchanged.
- Documented trade-off (code comment, `curriculum-map.md`, D-0008): two transactions
  re-parenting overlapping chains in opposite orders can deadlock; Postgres aborts one →
  generic `500 internal_error`, never a partial write, caller may retry.

### Incidental hardening

- A malformed (non-UUID) syllabus/source/parent id now maps to the same stable domain error as a
  missing one (`unknown_syllabus`/`unknown_source`/`invalid_parent`) via a Postgres `22P02`
  check, instead of a generic `500`.
- `randomSuffix()` in the integration tests was a per-process counter, so a second `go test` run
  against the same disposable database collided on the unique `content_sources.source_url`. It
  is now unique across runs (nanosecond timestamp + atomic counter).

## Schema decisions (also recorded in D-0008)

- **Parent-same-syllabus and no-cycle checks are application-layer**, not DB triggers: a bare
  trigger would either leak raw `RAISE EXCEPTION` text to the client or force Core to
  fragile-parse trigger message text to recover a stable error code. Instead, `postgres_store.go`
  validates inside the write transaction with `SELECT ... FOR UPDATE` row locks on the parent
  chain, so the check is race-safe and the error mapping stays exact (`ErrInvalidParent`).
- **`syllabusId` is immutable after creation** (no `PATCH` field for it): changing it would
  require re-validating an entire subtree's parent-syllabus invariant in one write. Creating a
  new node under the correct syllabus is simpler and cannot leave a partially-migrated
  hierarchy.
- **Source gate re-runs on every `contentSourceId` change**, not just at creation — a draft
  node could otherwise be repointed at an unapproved/mismatched source after creation.
- **`status` is never a `PATCH`-able field** — only `verify`/`retire` actions change it, so the
  lifecycle transition rules live in one place (`transitionStatus`) instead of being
  reachable through the general update path.
