## Delivered

Second secure web-to-Core editorial workflow, alongside T-0009: author, edit, review, verify,
and retire curriculum-map nodes for an active catalogue syllabus. Full architecture, security
model, role matrix, and UI state list are documented in `docs/editorial-curriculum-workflow.md`;
the design decision is `D-0012` in `docs/decisions.md`.

- Protected `/dashboard/editorial/curriculum` page (`apps/web`), gated to `editor`/`reviewer`/
  `admin`; `learner`/unknown see an "No editorial access" state and trigger zero API calls. A
  second gated nav entry ("Curriculum map") was added to `app/layout.tsx` next to "Editorial
  sources".
- Workspace UI: syllabus selector, node list (kind, label, computed hierarchy indent, parent
  code, lifecycle status badge, linked source title), create/edit form (kind, code, label,
  optional parent, approved-and-syllabus-linked source selector, optional locator; editable only
  while `draft`), and reviewer/admin-only verify/retire controls with an inline confirmation
  step. Reuses `app/dashboard/editorial/sources/styles.module.css`'s design language via CSS
  Modules `composes`; a small local stylesheet adds only the new status-badge color variants,
  syllabus picker, and hierarchy indent.
- BFF: `lib/editorial/core-proxy.ts`'s `EditorialOperation` union gained six variants
  (`listCurriculumMapNodes`, `getCurriculumMapNode`, `createCurriculumMapNode`,
  `updateCurriculumMapNode`, `verifyCurriculumMapNode`, `retireCurriculumMapNode`); no other
  change to that shared module. Six new route handlers under
  `app/api/editorial/curriculum-map/nodes/*`, each exporting only its allowlisted HTTP
  method(s).
- **Tiny, essential Core contract change** (pre-approved by the user before implementation — see
  "Plan-first questions" in `docs/tasks/active.md`): `GET /curriculum-map/nodes` and
  `GET /curriculum-map/nodes/{id}` now return nodes of any lifecycle status to a
  `curriculum_map:read` holder (editor/reviewer/admin only — no other consumer of that route
  exists), with an optional `status` filter on the list endpoint. No schema, migration,
  permission, or write-side rule changed. See `D-0008` "Update (T-0010)" and
  `docs/curriculum-map.md`.
- No content ingestion, OCR, AI generation, or copyrighted material of any kind. No node/source
  data created, seeded, approved, linked, verified, or retired by this agent — every action is
  an explicit human click through the new UI.

## Auth and fail-closed behavior

Unchanged from T-0009/D-0011 — this task added no new logic to `callCore`/`readSafeJsonBody`/
`http.ts`/`permissions.ts`/`role.ts`, only new `EditorialOperation` variants and route files that
delegate to the existing shared functions. Core remains the sole authorization authority; the
web role check is UI-visibility only. Verify/retire ignore any client body and always send `{}`
(same pattern as the existing approve route).

## UI flow/states

- `/dashboard/editorial/curriculum`: loading (`role="status"`), empty ("no nodes yet",
  `role="status"`), error banner with retry (`role="alert"`), syllabus picker, populated node
  list with hierarchy/status/source columns, create form, edit form (non-draft read-only
  notice, "cannot clear a required field" / "change at least one field" validation before any
  network call, explicit-clear support for the two nullable fields), verify confirmation, retire
  confirmation (an already-retired node offers no action), review controls hidden for `editor`.
- `learner`/unknown roles: "No editorial access" screen only; the workspace's data-fetching
  functions are never called (asserted by test).
