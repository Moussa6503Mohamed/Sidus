## Why a malformed id was ever a 500

Every affected table's `id` column is `UUID` (see migrations `0001`, `0005`, `0010`). A route like
`GET /content-sources/{id}` passed the path value straight into `WHERE id = $1`. For a well-formed
but missing UUID, Postgres returns zero rows (`sql.ErrNoRows`, already mapped to `ErrNotFound`).
For a malformed value (e.g. `GET /content-sources/not-a-uuid`), Postgres cannot even compare it to
the `UUID` column and raises `22P02` (`invalid_text_representation`) — a Go `*pq.Error`, not
`sql.ErrNoRows` — which fell through the existing `if errors.Is(err, sql.ErrNoRows)` check into
the generic `fmt.Errorf(...)` / `internal_error` 500 path. `curriculummap` had already fixed this
for its node-lookup helpers (`syllabusIsActive`, `validateSourceGate`, `validateParent`) in the
T-0006 review, but not yet for its own `{id}` path-parameter routes (`GetNode`, `UpdateNode`,
`transitionStatus`) — this task finishes that and applies the same fix to `contentsource` and
`catalogue`.

## Why a case-variant field was ever accepted

Go's `encoding/json` struct decoding matches field names **case-insensitively** by default, and
`json.Decoder.DisallowUnknownFields()` only rejects names with **no** case-insensitive match to a
struct field — it does not care which case matched. So `{"SyllabusCode": "0610"}` decoded straight
into a struct field tagged `json:"syllabusCode"` with `DisallowUnknownFields` silently satisfied.
`actorId`/`reviewerId` were already rejected in these three packages (no struct field of that name
exists, case-insensitively or otherwise), but a genuine case variant of a real field name was not.
The fix is the same one `question` used from the start (T-0007): decode into
`map[string]json.RawMessage` first, reject any key not in an explicit allowlist (which is
case-sensitive, because it is a plain Go map key comparison), then strict-decode the allowlisted
raw JSON into the destination struct.

## Update (T-0008 review)

**Finding:** every allowlist decoder (`decodeStrict` in `contentsource`/`catalogue`, plus
`curriculummap`'s inline `createNode` and `updateNode` decoders) decodes the request body into
`map[string]json.RawMessage`. Go's `encoding/json` decodes a body of literal `null` into that map
type successfully, producing a `nil` map with no error — `null` was never a valid JSON *object*,
but the decoder had no way to tell it apart from `{}`. A `nil` map has zero keys, so it passed the
allowlist loop (`for name := range raw` iterates zero times) and reached business validation
looking identical to an empty object: `create` returned `missing_required_fields`, `update`/PATCH
returned `no_updatable_fields`, `approve`/`reject` proceeded as if no reviewer fields were
supplied. `null` should be rejected as `400 invalid_json` at the same point every other malformed
body is, before any of that business logic runs.

**Fix:** each decoder now checks `raw == nil` immediately after the first successful `Decode(&raw)`
call and returns `400 invalid_json` (`writeError` in `contentsource`/`catalogue`,
`writeInvalidJSON` in `curriculummap`) before the trailing-data check, the allowlist loop, or any
store/event call. Valid `{}` still decodes to a non-nil empty map and is unaffected — create
endpoints still return `missing_required_fields`, PATCH endpoints still return
`no_updatable_fields`. No change to the allowlists, case-sensitivity, identity-field rejection, or
trailing-data rejection; no route, role, schema, migration, content-source state, or `question`
package change.

Files changed: `services/core/internal/contentsource/handlers.go`,
`services/core/internal/catalogue/handlers.go`, `services/core/internal/curriculummap/handlers.go`
(both the `createNode` allowlist decoder and the separate `updateNode` decoder).

Tests added — one `null`-body case per affected body shape, each asserting `400 invalid_json` and
zero store mutation:

- `contentsource/handlers_test.go`: `TestCreate_RejectsNullBody`, `TestUpdate_RejectsNullBody`,
  `TestApprove_RejectsNullBody`, `TestReject_RejectsNullBody`.
- `catalogue/handlers_test.go`: `"null body"` case added to `TestCreateSubject_StrictJSON`,
  `TestCreateSyllabus_StrictJSON`, `TestUpdateSyllabus_StrictJSON`.
- `curriculummap/handlers_test.go`: `"null body"` case added to `TestCreateNode_StrictJSON` and
  `TestUpdateNode_ForbiddenAndUnknownFields_Returns400` (the latter covers `updateNode`'s separate
  decoder via its existing `assertUnchanged` no-mutation check).

All existing `{}`-behavior tests continue to pass unchanged.
