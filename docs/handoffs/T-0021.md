## Update (T-0021 review fix)

Two review findings fixed on top of the base implementation, `services/core` only:

- **`sourceUrl` was never canonicalized before storage.** `create` and `update` validated
  `isValidSourceURL(s)` against `strings.TrimSpace(s)` internally but then stored the raw,
  untrimmed request value. A value like `"  https://example.org/x  "` or a private URI padded
  with outer whitespace would validate but persist with the padding intact. Both handlers now
  trim once, only after validation succeeds, and store the canonical trimmed value:
  `services/core/internal/contentsource/handlers.go` `create` (after the `isValidSourceURL`
  check, before `resolveSyllabus`/`store.Create`) and `update` (same point, operating on the
  `*string` field). No change to `isValidSourceURL`/`isValidHTTPURL`/`privateSourceURIPattern`
  themselves — they already matched on a trimmed copy for the accept/reject decision; only the
  stored value changed. A value that is entirely whitespace still rejects before any store call
  via the pre-existing blank-field checks (`missing_required_fields` on create,
  `blank_fields` on update) — trimming does not change that path.
- **Missing explicit regression coverage** for `localhost`/traversal/backslash rejection and for
  canonical-trim storage. Added to `services/core/internal/contentsource/handlers_test.go`:
  - `invalidSourceURLs` (shared by `TestCreate_SourceURL_InvalidMatrix` and
    `TestUpdate_SourceURL_InvalidMatrix`, so both create and PATCH are covered from one table)
    gained bare `"localhost"`, `".."`, `"\\"` tokens, `localhost`/`user@localhost` attempted as
    an alternate host on the private scheme, `..` path-traversal injected at two positions in the
    private scheme, and backslash injected at three positions in the private scheme (Windows-path
    style bypass attempts). One candidate case, `http://localhost/../licensed/...` as a *plain
    http URL*, was tried and reverted — it is syntactically a valid absolute `http` URL (scheme
    `http`, host `localhost`), so per the unchanged-HTTP/HTTPS-behavior rule it must stay
    **accepted**, not rejected; asserting 400 for it would have been asserting a regression, not
    catching one. Local Go test run caught this before commit (see below).
  - `TestCreate_SourceURL_TrimsSurroundingWhitespace` / `TestUpdate_SourceURL_TrimsSurroundingWhitespace`:
    both an ASCII-tab/newline-padded `http` URL and a space-padded private URI round-trip to the
    exact trimmed canonical string on create and on PATCH. One case pads with real U+00A0
    (no-break space, UTF-8 `0xC2 0xA0`), not just ASCII space/tab/newline, so the assertion
    exercises `strings.TrimSpace`'s full Unicode behavior rather than an ASCII-only trim.
  - `TestCreate_SourceURL_BlankAfterTrim_Returns400` / `TestUpdate_SourceURL_BlankAfterTrim_Returns400`:
    an all-whitespace `sourceUrl` (tab/newline/space only) is rejected before any store call and
    before any audit event, confirming trimming did not loosen the existing blank-value gate.
- No change to D-0021's URI acceptance/rejection grammar, the approval gate, roles/permissions,
  API error codes, or existing HTTP/HTTPS validation semantics. No migration, runtime source row,
  approval, question, rubric, AI, auth, or learner change. No dependency change.
