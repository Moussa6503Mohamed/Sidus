# T-0033 handoff — Sonnet adapter and automated quality gate

## Status

In review. Stop condition per `docs/tasks/active.md`: live API tests remain deferred until the
API-configuration phase.

## Delivered

- `services/ai/app/sonnet/schemas.py` — strict pydantic `SonnetRequest`/`SonnetResult` contracts
  (`extra="forbid"`, unique-criteria validation). Request fields mirror the canonical explanation
  cache key from `CLAUDE.md` (question + syllabus + rubric + language + explanation version);
  `SonnetResult` carries model, confidence, per-criterion marks/feedback, and token/cost usage.
- `services/ai/app/sonnet/provider.py` — `SonnetProvider` protocol and `get_provider()`, which
  always returns `None` in this build (fail-closed; overridable in tests, same pattern as
  `app.auth.get_authenticator`). No live Anthropic call exists yet — see Boundaries below.
- `services/ai/app/sonnet/fake_provider.py` — deterministic `FakeSonnetProvider` for tests: a pure
  function of the request by default, or a scripted response queue for specific scenarios.
- `services/ai/app/sonnet/quality_gate.py` — deterministic rubric/consistency validation. Missing/
  unknown/duplicate criteria or marks exceeding a criterion's cap withhold immediately (never
  retried — retrying cannot fix an invalid shape). Confidence below 0.6 alone retries.
  `check_consistency()` compares two attempts' marks and withholds on disagreement beyond
  tolerance.
- `services/ai/app/sonnet/jobs.py` — durable `JobStore` protocol and a `SqliteJobStore`
  implementation. Each attempt (provider call + gate verdict) is an append-only trace row: model,
  cost, confidence, verdict, reasons. Job state and its full trace survive reopening the store
  against the same file (`test_durability_survives_reopening_the_store`).
- `services/ai/app/sonnet/orchestrator.py` — `run_job()`: provider call -> quality gate -> cross-
  attempt consistency check -> retry (up to 3 attempts) or withhold. A provider error counts as a
  retryable attempt. Never fabricates a result: every non-accepted path ends in `WITHHELD` with a
  full trace, never `SUCCEEDED` with invented output.
- `services/ai/app/sonnet/routes.py` — `POST /sonnet/jobs` (submit + run synchronously) and
  `GET /sonnet/jobs/{id}` (fetch state + trace), both behind the existing `require_clerk_session`
  dependency. Submission fails closed with `503` when `get_provider()` returns `None`. Every job
  is owner-scoped to `principal.subject`; a job owned by a different principal returns `404`
  (never `403`, so existence doesn't leak) identical to an unknown `job_id`. A duplicate
  client-supplied `job_id` returns `409` via a structured `JobIdConflict` rather than an unhandled
  SQLite `IntegrityError`.
- Wired into `services/ai/app/main.py` alongside the existing ingestion router.

An independent review pass (`ecc:code-reviewer`) ran before this handoff and found two HIGH issues
(missing owner scoping on job reads; unhandled crash on duplicate `job_id`) and one MEDIUM
(`cache_key()`'s `"|"` join was not collision-free across fields). All three are fixed above and
covered by new tests; see D-0026 for the resulting design.

## Boundaries respected

- No `ANTHROPIC_API_KEY`, no live Anthropic HTTP call, no PDF/OCR/extraction, no question
  rewriting, no content seeding. `get_provider()` is unconditionally `None` — the real
  Anthropic-backed implementation is deferred to the API-configuration phase named in
  `docs/mvp-execution-plan.md`.
- Model output never auto-creates or publishes learner content: the adapter only produces a
  `SonnetResult` held inside a job record: nothing here writes to Core, questions, or rubrics.
- Fully automated: a withheld job stays withheld. There is no human-reviewer routing in this
  surface (per `docs/mvp-execution-plan.md`'s AI-first gate).
- Tests use only the deterministic `FakeSonnetProvider` — no network access, no real model calls.

## Security

- Both routes require a verified Clerk session (`require_clerk_session`), matching the existing
  ingestion router pattern.
- Request/result schemas are `extra="forbid"` — an unexpected field from any caller or provider
  response is rejected rather than silently accepted.
- The job store never contains raw source text or PDFs: only opaque IDs, structured marks/
  feedback, and cost/usage numbers.
