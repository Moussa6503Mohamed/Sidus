## Delivered

- New Core `services/core/internal/learner` package: independent `Projection`/`Option` types
  (no import of `question`), `Store` interface, `PostgresStore` (a single joining SQL query is
  the sole eligibility authority, re-evaluated on every read), and `GET /learner/questions` /
  `GET /learner/questions/{id}` handlers. The editorial `question` package, its routes, and
  `question:read` are untouched.
- New `learner_question:read` permission in `services/core/internal/auth`, held by every
  recognized role (`learner`, `editor`, `reviewer`, `admin`); unknown/missing role denied.
  Registered in `services/core/main.go` alongside the other packages.
- New web BFF: `apps/web/lib/learner/core-proxy.ts` (separate `LearnerOperation` union and
  `callCoreLearner`, GET-only, same fail-closed/redirect-refusal/5xx-sanitization contract as
  the T-0009 editorial BFF) and `apps/web/lib/learner/http.ts`. Route handlers under
  `apps/web/app/api/learner/questions/*`.
- New `/dashboard/practice` screen (`apps/web/app/dashboard/practice/*`): role-gated access
  (`canAccessPractice` — any recognized role), a syllabus-id/optional-node-id form, loading/
  error-with-retry/empty/loaded states, and MCQ options rendered as selectable buttons with only
  local highlight state — no submit, mark, reveal, timer, attempt, or AI call anywhere. Nav link
  added to `apps/web/app/layout.tsx` (visible to any signed-in recognized role).
- Shared contract `LearnerQuestion`/`LearnerQuestionOption` added to
  `packages/shared/src/contracts.ts`, written by hand (does not extend `Question`) so a future
  edit to the editorial type cannot widen the learner projection.
- `docs/learner-question-delivery.md` (projection, eligibility gate, threat boundary, known
  exclusions), D-0017 in `docs/decisions.md`, and this handoff.
- No SQL migration — the projection reads existing columns only. No editorial route, schema,
  role/permission beyond the additive one, or business rule changed.

## Decisions / assumptions

- No learner-facing curriculum-catalogue/curriculum-map browse endpoint was added; the practice
  screen's syllabus/node inputs are plain validated ID fields. See D-0017 "Alternatives".
- `GET /learner/questions/{id}` requires no `syllabusId`; an ineligible or nonexistent question
  returns the identical `404` either way.
- Integration test function names were given the `_Integration_` marker (matching the existing
  `question`/`curriculummap`/`contentsource`/`catalogue` convention) so `-run Integration`
  selects them.
