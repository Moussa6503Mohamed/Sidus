## Delivered

- New Core `services/core/internal/learner` package: independent `Projection`/`Option` types
  (no import of `question`), `Store` interface, `PostgresStore` (a single joining SQL query is
  the sole eligibility authority, re-evaluated on every read), and `GET /learner/questions` /
  `GET /learner/questions/{id}` handlers. The editorial `question` package, its routes, and
  `question:read` are untouched.
- New `learner_question:read` permission in `services/core/internal/auth`, held by every
  recognized role (`learner`, `editor`, `reviewer`, `admin`); unknown/missing role denied.
  Registered in `services/core/main.go` alongside the other packages.
- New web BFF: `apps/web/lib/learner/core-proxy.ts` (separate `LearnerOperation` union and
  `callCoreLearner`, GET-only, same fail-closed/redirect-refusal/5xx-sanitization contract as
  the T-0009 editorial BFF) and `apps/web/lib/learner/http.ts`. Route handlers under
  `apps/web/app/api/learner/questions/*`.
- New `/dashboard/practice` screen (`apps/web/app/dashboard/practice/*`): role-gated access
  (`canAccessPractice` — any recognized role), a syllabus-id/optional-node-id form, loading/
  error-with-retry/empty/loaded states, and MCQ options rendered as selectable buttons with only
  local highlight state — no submit, mark, reveal, timer, attempt, or AI call anywhere. Nav link
  added to `apps/web/app/layout.tsx` (visible to any signed-in recognized role).
- Shared contract `LearnerQuestion`/`LearnerQuestionOption` added to
  `packages/shared/src/contracts.ts`, written by hand (does not extend `Question`) so a future
  edit to the editorial type cannot widen the learner projection.
- `docs/learner-question-delivery.md` (projection, eligibility gate, threat boundary, known
  exclusions), D-0017 in `docs/decisions.md`, and this handoff.
- No SQL migration — the projection reads existing columns only. No editorial route, schema,
  role/permission beyond the additive one, or business rule changed.

## Update (T-0015 review fix)

Two review findings fixed on top of the original `d60f6e8` delivery. Status stays `review`; not
released, not pushed.

### Delivered

- **Finding 1 (canonical-rubric ownership gate):**
  `services/core/internal/learner/postgres_store.go`'s `eligibleQuestionsQuery` now joins
  `question_rubric_versions rv ON rv.id = q.canonical_rubric_version_id AND rv.question_id = q.id`
  (previously missing the `rv.question_id = q.id` ownership check). New integration regression
  `TestPostgresStore_Integration_CanonicalRubric_OwnershipGate` in `postgres_store_test.go`: seeds
  two otherwise-eligible questions, points question A's `canonical_rubric_version_id` at question
  B's verified current-revision rubric via direct disposable-test setup, and asserts A is excluded
  from `GetQuestion`/`ListQuestions` while B stays eligible and unaffected. No canonical-rubric
  fallback path exists anywhere in the package (confirmed by inspection of the single query).
- **Finding 2 (learner-safe active-syllabus discovery):** New `GET /learner/syllabuses` Core
  route (same `learner_question:read` permission; `services/core/internal/learner/{model,store,
  postgres_store,handlers}.go`) returning a hand-written `Syllabus` projection (`id`, `board`,
  `syllabusCode`, `qualification`, `track`, `displayName`) for `active` catalogue syllabuses only,
  read directly from the `syllabuses` table. New web BFF operation `listLearnerSyllabuses` in the
  same closed `LearnerOperation` union (`apps/web/lib/learner/core-proxy.ts`), new route handler
  `apps/web/app/api/learner/syllabuses/route.ts`, and new shared type `LearnerSyllabus`
  (`packages/shared/src/contracts.ts`). `/dashboard/practice`'s `PracticeWorkspace` now fetches
  the syllabus list on mount (loading/empty/error-with-retry states) and renders an accessible
  `<select>` instead of a raw-UUID text field; eligible-question fetching still never runs until
  the learner explicitly selects a syllabus and submits. The optional curriculum-map node filter
  remains a plain text field, now explicitly labelled "temporary, developer-only" — no
  learner-facing curriculum-map browse endpoint was added.
- Docs: `docs/learner-question-delivery.md` and `docs/decisions.md` (D-0017) both gained an
  "Update (T-0015 review)" section describing both fixes.
- No SQL migration (both fixes read/query existing columns only). No editorial route, schema, or
  business rule changed. No new permission — `GET /learner/syllabuses` reuses
  `learner_question:read`.
